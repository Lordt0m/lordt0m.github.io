Nobelese

A Django REST appointment API with explicit access and confirmation rules.

An independent demonstration of public availability, staff review, and booking confirmation for a fictional law practice.

Inspect source and API examples
Fictional demonstration: Ojo & Associates is the project scenario. No live law practice, client engagement or real customer records are implied.

The problem

A consultation request is not yet a booking. Availability can change between submission and staff review, and different staff members should not see or control the same records. The API needs to preserve those distinctions at its server boundary.

What I built

Public endpoints expose practice areas, lawyer profiles and calculated slots. Requests enter a pending state. Token-authenticated administrators can review, confirm or decline requests, while lawyer access is restricted to their assigned appointments.

A guarded confirmation workflow

  1. Read the pending request inside an atomic transaction and lock its record.
  2. Select and lock an eligible lawyer, then recheck availability.
  3. Create the confirmed appointment with a database uniqueness constraint.
  4. Return a conflict when the requested confirmation can no longer succeed.

Working hours and time-off rules also guard existing confirmed appointments. The source keeps these operations in explicit services rather than relying on client-side checks.

How to inspect it

The repository README contains setup instructions, endpoint examples and the request-to-confirmation flow. Local setup exposes OpenAPI documentation at /api/docs/. Review booking/services.py, booking/permissions.py and the PostgreSQL CI configuration alongside the tests.

Scope and verification

The README and selected permission and confirmation implementation were inspected on 13 November 2026. The project test suite was not rerun for this portfolio update, and no currently working public API endpoint was verified.

All practice, client and lawyer records are synthetic. This is software portfolio work, not employment by or paid delivery for a law-firm client. The read-only demo configuration is a documented boundary, not a claim that a current public deployment was tested.
