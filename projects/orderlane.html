Orderlane

From menu to ready, with the rules in the API.

A compact, independent food-ordering concept connecting a customer menu, vendor desk and transactional backend.

Try OrderlaneInspect source and tests
Independent concept: Inspired by FufuPlanet's advertised ordering features. No affiliation, client work, payments or delivery. All restaurants and orders are fictional.

Try it in two minutes

  1. Add a meal in Customer view and place an order.
  2. Open Vendor desk, select the same restaurant and accept the order.
  3. Move it through preparing, ready and completed, then return to Customer and refresh.
  4. Open Under the hood and run the live API checks. Expand the log to see requests and actual responses.

What the interface proves

A usable ordering flow includes quantity limits, a clear basket, server-calculated totals, loading and failure states, and a safe retry action. The vendor desk turns explicit order stages into clear actions. The frontend uses semantic HTML, responsive CSS and a small vanilla JavaScript interface without a framework build.

What the API enforces

  • Price integrity: meal prices and totals come from the server catalogue; client-supplied prices are ignored.
  • Request replay: a unique workspace/request-key constraint returns the original order for an identical submission and rejects a changed payload under the same key.
  • Restaurant scope: vendor list, detail and update queries include the session workspace and restaurant. Another restaurant's order ID returns 404.
  • Safe transitions: each stage requires the current revision. An atomic conditional update rejects a stale revision or skipped stage.
  • Audit history: each successful status and its event are committed in the same database transaction.

Verification

On 13 November 2026, all 23 Django API tests passed locally and in the Render build. Tests cover request replays, changed-payload conflicts, restaurant and browser-workspace isolation, CSRF, invalid inputs, legal stages and stale revisions. Live HTTP checks confirmed order creation, identical replay, a cross-restaurant 404 and every stage through completion. HTML, CSS and JavaScript returned successfully.

The local customer interface and ordering action were exercised. A browser connection failure prevented completing hosted and mobile visual verification. No claim of a complete accessibility audit, load testing or PostgreSQL concurrency testing is made.

Scope choices

The role selector is intentionally a demo device, not production authentication. Browser sessions isolate fictional workspaces. SQLite keeps deployment small; data on the free service filesystem can reset. Real tenant memberships, durable database hosting, payment processing, notifications and delivery integrations are outside this slice.

The concept demonstrates contribution to an existing product workflow. It does not imply that FufuPlanet lacks these capabilities.
