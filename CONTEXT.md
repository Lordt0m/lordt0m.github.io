# Developer Portfolio

The portfolio presents inspectable evidence that Ayotomiwa Ojo can build, understand, explain, test, debug, and ship Python and Django software.

## Language

**Portfolio**:
The complete public evidence surface, including its page, downloadable CV, project links, and verified claims.
_Avoid_: Personal brand ecosystem, platform

**Claim**:
A public statement about Ayotomiwa's skills, work, availability, or a project's behaviour.
_Avoid_: Marketing copy, boast

**Evidence**:
An inspectable source that supports a Claim, such as a repository, live deployment, test result, screenshot, decision record, or downloadable artifact.
_Avoid_: Content, proof point

**Evidence State**:
The current publication status of a Claim: `verified`, `withheld`, or `planned`. Only verified Claims appear as facts on the public site.
_Avoid_: Done, almost done

**Featured Project**:
A project presented with its user problem, delivered behaviour, engineering decisions, Evidence, and direct inspection links. ShelfSum is the first Featured Project.
_Avoid_: Main project, big project

**Supporting Project**:
A smaller project that proves a narrower capability without requiring a full case study. Credence is the first Supporting Project.
_Avoid_: Minor project, filler project

**Project Proof Block**:
The smallest complete presentation of a project: problem, solution, selected engineering evidence, technology, and inspection actions.
_Avoid_: Project card, tile

**Inspection Action**:
A link that lets a reader verify work directly, such as `Live Demo`, `Source Code`, `View Case Study`, or `Download CV`.
_Avoid_: CTA, button

**Release Evidence**:
The recorded automated and manual checks that justify publishing the current Portfolio version.
_Avoid_: QA notes, test dump
